# 重构审计手册（assets/refactor-playbook.md）

> 触发时机：**评估 / 重构一个已有的 agent 架构**（存量系统）。与新建流程（SKILL.md 工作流·新建轨）分轨，不混写。
> 两轨共享：澄清问卷（assets/clarification-playbook.md）与生产级检查（references/production-checklist.md）。
> 框架依据：references/h-framework.md（六层 + P + 模型组合）；产出模板见本文件「重构评估报告模板」。

## 一、逆向审计四步

### 第 1 步：收集

收集存量系统的事实材料，**只收集、不评判**：

- 代码：执行循环、工具注册、上下文组装、状态持久化、钩子/权限、评估脚本的实际实现。
- 文档：现有设计文档、README、运维手册（有则读，无则标注"文档缺失"本身就是一个缺口）。
- 运行记录：日志、轨迹、成本账单、失败案例、延迟分布（有多少用多少，没有就标注"无可观测数据"）。

### 第 2 步：映射（现状映射表）

把收集到的现状**逐条映射**到 H 框架，产出现状映射表：

- 六层 E/T/C/S/L/V：每层现状是什么实现、有没有实现。
- 范式 P：扩展方式 / 配置方式 / 部署拓扑 / 编排模式的现状。
- **模型组合现状**：当前用几档模型、每个步骤用哪档、有没有分派依据、成本结构如何。
- 映射不上的部分单列「框架外现状」，不硬塞。

### 第 3 步：诊断

对照三套判据找缺口，**每个缺口定级**：

- 判据一：六层必答问题（h-framework.md 各层的必答问题清单）。
- 判据二：生产级七项（production-checklist.md）。
- 判据三：模型分派表（任务-模型分派是否成立、级联升级条件是否存在、升级率是否被监控）。

缺口定级（四档）：

| 级别 | 含义 |
|---|---|
| 阻断 | 不修则系统不可用 / 有确定性故障 |
| 风险 | 不修则特定条件下故障（安全/一致性/失控） |
| 优化 | 可用但质量/效率有明确提升空间 |
| 成本浪费 | 功能正确但资源错配——典型是"用大炮打蚊子"的模型档位错配 |

### 第 4 步：方案（重构决策卡）

产出重构决策卡，四个必答项：

1. **改什么**：按缺口级别排序的改动清单（阻断 > 风险 > 成本浪费 > 优化）。
2. **不改什么**：明确保留的现状 + 理由（克制：不为重构而重构）。
3. **迁移顺序**：改动的依赖序与可独立验证的最小步。
4. **回滚点**：每一步的回滚方式（无回滚点的改动必须显式标注并升高风险级别）。

## 二、重构场景特别提示

存量系统最常见的两类重构收益：

1. **架构缺口修复**：六层缺位（常见：无 V 层、S 层无持久化、L 层无拦截）导致的隐性故障。
2. **模型降档省钱**：识别"用大炮打蚊子"的步骤——把窄决策/高频重复步骤从强力档降到快速低价档或确定性规则。**单智能体循环内的步骤降档同样适用，不限于多智能体**；降档前先按模型组合必答问题确认分派依据与级联升级条件，降档后监控升级率（升级率过高 = 降档失败，回查分派表）。
