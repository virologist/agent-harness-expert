# 澄清与协作手册（assets/clarification-playbook.md）

> 唯一定义处：澄清问卷的**规则、维度**与五个协作设计手段都在这里。SKILL.md 只放指针。
> **问卷模板唯一来源 = `scripts/render_questionnaire.py`**（`--dims`/`--all`，纯模板变换），维度表见 §三。

## 一、五个协作设计手段（全程贯穿）

| # | 手段 | 做法 |
|---|---|---|
| 1 | 追问优先于给选项 | 能问"为什么"就不急着给选项；但作为架构师，先给专业判断，再用追问确认用户真实意图 |
| 2 | 一致性质问器 | 某层做了选择后追问："这个原则为什么只在这一层？""有没有特权部分？""这条边界为什么停在这里？" |
| 3 | 跨领域模式对照库 | 抛"对照物 + 问题"（"别人这样解类似问题，你的问题哪里像、哪里不像？"），激发跨领域迁移 |
| 4 | 魔鬼代言人 | 每个方案成型后主动构造反例："这个设计在 X 情况下会崩"，逼方案更健壮 |
| 5 | 诚实标注未知区 | 主动列出框架没覆盖的维度，不假装全覆盖 |

## 二、问卷规则

| 规则 | 行为 |
|---|---|
| 一次性列出 | 把所有需澄清的问题**一次性列出**（生成 md 问卷），禁止逐轮追问 |
| 先提取已有 | 先扫描用户已说 / 已提供的内容，映射到 11 个维度，标记「已明确」 |
| 只问缺失 | 只列用户还没提供的维度；信息很少时完整列出，信息较多时只列缺的那几项。**绝不重复问** |
| 用户三种方式 | ① 对话框直接答 ② md 填写后一次性发回 ③ 说"你来做"→ 给参考答案 |
| 参考答案写法 | 对**每个问题**都给明确建议 + 标注"默认假设，可推翻" + 说明依据（知识库案例/模式） |
| 缺项处理 | 用户只答了部分，剩余按参考答案补齐并标注，进入设计前请用户统一确认 |
| 每题写"为什么问" | 写清它影响哪一层，让用户理解价值，而不是被审问 |

## 三、十一个澄清维度（Q1–Q11）

| id | 维度 | 影响层 |
|---|---|---|
| goal | 目标与用途 | 六层方向 |
| success | 成功标准 | V |
| oracle | 验收来源（怎么知道做对了） | V |
| task | 任务结构 | E |
| data | 数据 / 资源边界 | T / L |
| constraint | 硬约束 | 取舍边界 |
| user | 用户与场景 | P / L |
| boundary | 边界（明确不做什么） | L 拒绝清单 |
| stack | 技术栈约束 | 可编码前提 |
| model | 模型策略与成本 | E / 模型组合 |
| efficiency | 效率与体感 | C / E |
