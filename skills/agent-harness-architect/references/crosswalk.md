# 三套分类法交叉映射表（Crosswalk）

> 本表把本包内并存的三套分类法**串成一张**，是它们之间的**唯一联结点**。
> 任何一套分类法变更（增删条目、扩缩范围、改编号），**必须同步本表**，否则再次变成孤岛。

## 一、为什么需要这张表（事实陈述）

本包内长期并存四套**功能相近但无人维护的对应关系**的分类法：

| 套 | 出处 | 颗粒度 | 主要用途 |
|---|---|---|---|
| ① 澄清 11 维度 | `assets/clarification-playbook.md` §三（Q1–Q11） | 11 维（goal/success/oracle/task/data/constraint/user/boundary/stack/model/efficiency） | 启动设计前的需求澄清问卷 |
| ② H 框架 49 问 | `references/h-framework.md`（总定义 6 问 + 六层 43 问 = 49） | 49 问（E9 / T7 / C8 / S6 / L6 / V7 + 模型组合 6） | 设计阶段必须答完的最低检查面 |
| ③ checker 三套 | `scripts/check_design_doc.py` 的 `HEADINGS`（15）+ `MUST_ANSWER`（9）+ `QUESTION_KEYWORDS`（43） | 共 67 项门禁（结构自检） | 设计文档提交前的脚本化结构门禁 |
| ④ production-checklist | `references/production-checklist.md` 三门槛 + 六层 + 横切 + 多 Agent | 50+ 条通用检查点 | 通用生产级自查清单 |

**历史坑**：同一个关注点（如「验收来源」「失败回喂」「评估者分离」）被这四套体系分别以**不同编号、不同粒度、不同表述**独立记录。改任何一套（如给 H 框架加一问）——另外三套不会跟随——结果就是"改了 A 套，B 套仍按旧数判定通过"或"漏检某个本属于同一条关注点的细节"。

**本表的作用**：把同一个关注点在四套体系里的对应条目**对齐到同一行**，让"改一处 = 改全套"成为可执行动作。本表是三套分类法的**唯一联结点**（强调：仅此一处，无第二份）。

## 三、维护协议

**本表是三套分类法的唯一联结点**（强调：仅此一处，无第二份）。任何分类法变更必须按下表执行同步：

| 触发动作 | 同步对象 | 最小同步动作 |
|---|---|---|
| 改 / 删 ① 套维度（如把 `boundary` 拆为 `boundary-in/out`） | 本表 §二 | 改对应行的"澄清维度"列；新增关注点则加一行 |
| 改 / 删 ② 套 H 框架问号 | 本表 §二 + `scripts/check_design_doc.py` 的 `QUESTION_KEYWORDS` | 改对应行的"H 框架问号"列；`QUESTION_KEYWORDS` 必须同步增删 |
| 改 / 删 ③ 套 checker 项（HEADINGS / MUST_ANSWER / QUESTION_KEYWORDS） | 本表 §二 + 对应的源文件 | 改对应行"checker 项"列；保持行数对齐，不静默删行 |
| 改 / 删 ④ 套 production-checklist 条目 | 本表 §二 + `references/production-checklist.md` | 改对应行"production-checklist 条目"列；新增条目必有对应关注点行 |
| 增新关注点（新维度 / 新问 / 新门禁 / 新检查点） | 本表 §二 | 必须在本表先建行，再回去改源文件——避免再次出现"加了一问但其他三套不知道"的孤岛 |

### 强制纪律

1. **任何一套分类法的变更 PR 必须同时包含本表的对应行更新**。PR 评审的第一关就是「本表是否同步」。
2. **本表的「关注点列」是稳定锚**：四个分类法的条目按关注点对齐，跨套的对应关系不靠编号对齐（编号会变，关注点不变）。
3. **不静默删行**：删除某行必须明确写「移除理由 / 移并到第 N 行」，保留审计轨迹。
4. **遇到盲区（—）**：当一个关注点在某套完全没记录时，列内填「—」并保留行；这是发现「分类法覆盖盲区」的信号源，不可为了表好看而删行。

### 与本表相关的三件事分工宪法

- **本表维护是「设计纪律」事项**（哪套覆盖了什么、跨套对齐是否对齐），归 **人 / 架构师**，由 PR 评审把关。
- **「关注点本身是否成立 / 是否答对了」是「语义判断」事项**，按三件事分工宪法归 **LLM / 架构师**，本表不做规则匹配。
- **「关键词是否在文档里出现」是「结构完整性」事项**，归 **`scripts/check_design_doc.py`**，本表不抢它的活。
