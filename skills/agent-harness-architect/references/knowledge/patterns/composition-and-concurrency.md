# 组合与并发类模式（5 条）

> 本组模式主要迁移到 **P（架构范式/编排）**、**S（状态）**、**E（执行循环）**。
> 每条含「核心思想 / 可迁移层 / 案例 / 何时不用 / 对照问题」。对照问题是抛给用户的，不是答案。

---

### Pure Function / Effect System（纯函数 / 效应系统）· 来源：编程语言

**核心思想**：把"副作用"显式化、类型化：一个组件的效应（它能改什么、依赖什么）被声明出来，而不是隐式藏匿。副作用可追踪、可组合、可推理，甚至可回滚。

**可迁移到**：S（状态）、P（架构范式）

**案例**：DeepSeek Harness 的 Cordis 时空可组合性（effect/coeffect 从编译期提升为运行时机制）。

**何时不用 / 代价**：副作用全部显式化 = 大量样板与类型标注；effect/coeffect 系统学习曲线陡；运行时解释 effect 有性能开销；与既有"随手 IO"的代码库整合成本高。**不要**在副作用稀少简单、团队不熟函数式、或性能极敏感时用。

**对照问题**：你的每个组件"能产生什么副作用、依赖什么"，是显式声明的还是隐式的？若要求"卸载后副作用必须完全回滚"，架构需要什么样的运行时支撑？

---

### Actor Model（Actor 模型）· 来源：并发 / 分布式

**核心思想**：系统由隔离的"actor"组成，每个 actor 有自己的状态，彼此只通过异步消息通信，不共享内存。天然隔离、天然并发、崩溃可独立恢复。

**可迁移到**：P（编排模式）、E（子代理隔离）

**案例**：Claude Code 的 subagents（隔离上下文，只回传结果）；多智能体系统中的子代理隔离。

**何时不用 / 代价**：消息传递式调试难（无共享调用栈）；要处理邮箱背压/溢出；监督与定位策略需额外设计；跨 actor 强一致事务很难；消息顺序与时序假设易踩坑。**不要**在共享内存已足够、并发度低、或业务需要跨实体强一致事务时用。

**对照问题**：你的子代理/子任务之间是共享状态还是消息隔离？一个子代理崩溃会不会污染主循环？隔离边界应该划在哪？

### Model Cascade / Task Routing（模型级联与任务路由）· 来源：成本工程 / 服务分层

**核心思想**：不同步骤按能力需求分派不同档位的模型——窄决策/高频重复步骤用快速低价档，复杂推理用强力档，并定义级联升级条件（低档置信度不足时升档重试）。成本驱动的"任务-模型分派"，而非全循环统一用一档。

**可迁移到**：E（执行循环内分档）、P（编排）、V（评估者档位）

**案例**：知识库模型条目（models/core/）中的决策型模型与生成式模型构成档位对照；单智能体循环内分档（形态 B）是本模式的主战场。

**何时不用 / 代价**：分档判据本身需要标定（哪些步骤真能用低档，需实测而非拍脑袋）；级联升级阈值定错会两头亏——阈值太松质量掉、太紧升级率飙升成本反超高配单模型；多档并存增加可观测性负担（每档的延迟/成本/失败率要分开监控）；升级率过高 = 分档失败，应回查任务-模型分派表而非调阈值。**不要**在任务同质、或窄决策占比极低时用——分档收益覆盖不了标定与运维成本。

**对照问题**：你的循环里每一步都用同一档模型吗？哪些步骤是"封闭答案集、高频重复"的窄决策？如果给每步标一个"所需能力档位"，有几步能用更低档？升级条件是什么、升级率监控了吗？

### System1-System2 Dual Model（System1-System2 双模型协作）· 来源：认知科学 / 决策理论

**核心思想**：快思考（System One，毫秒级、低成本的类型化决策模型）与慢思考（System Two，生成式强力模型）分工：快模型承接高频窄决策与初筛，慢模型只在快模型不确定或任务复杂时介入。本质是把"直觉"与"推理"拆成两个可独立选型的组件。

**可迁移到**：E（循环内分档）、L（快筛门控）、V（独立裁判）

**案例**：知识库模型条目中的决策型模型（System One 物种）+ 生成式强力 LLM 的组合；快筛门控（L 层）用快模型做注入/合规初筛。

**何时不用 / 代价**：双系统 = 两套接口、两套失败模式、两套监控；快慢之间的交接协议（何时升级、传什么上下文）需要显式设计，交接丢信息是常见故障；快模型的校准漂移（分布变化后置信度失真）需要定期复核；供应商锁定风险——快模型若是专有 API，替换成本随耦合深度上升。**不要**在窄决策占比低、或团队无力维护两套模型生命周期时用。

**对照问题**：你的系统里"直觉判断"（分类/路由/门控）和"深度推理"是同一个模型在做吗？如果拆开，快模型的置信度多久复核一次？快慢交接时传的是全量上下文还是摘要？

### Confidence-Gated Control Flow（置信度门控控制流）· 来源：控制系统 / 可靠性工程

**核心思想**：把模型输出的置信度（概率/评分）作为控制流的一等信号：高置信直接放行，低置信触发升级（升档模型/人工复核/拒绝执行）。控制流由"模型有多确定"驱动，而非固定步数。

**可迁移到**：E（循环终止/升级）、L（门控）、V（验证强度阶梯的独立裁判档）

**案例**：级联升级条件（低置信升档重试）；快筛门控阈值（低于阈值拒绝并升级人工）；验证强度阶梯中"独立模型裁判 + 显式标准 + 迭代预算"的组合。

**何时不用 / 代价**：置信度本身需要标定与校准（未校准的概率当门控阈值用 = 用噪声做决策）；校准随数据分布漂移，需要周期性复核（校准漂移）；门控阈值是业务权衡（误放行 vs 误拦截的代价不对称），不存在通用最优值；置信度不可得的模型（部分 API 不返回概率）无法直接用本模式。**不要**在置信度无来源、或业务无法承受门控误判代价时用。

**对照问题**：你的循环里，"模型说它不确定"时发生什么？置信度是模型原生输出还是你拍的？门控阈值是怎么定的、多久复核一次？低置信样本升级后，升级率被监控了吗？
