# 生产级设计检查清单（Production Checklist）

> 通用检查点，适用于**任何** Agent Harness 架构设计，与具体项目无关。交付设计文档前逐项自查。
> 「可编码三门槛」的**唯一定义处**在本文件；其他文档只放指针。
> 可用 `scripts/check_design_doc.py <设计文档路径>` 做结构自检（缺哪些项由它报，要不要补由你判断）。

## 可编码三门槛（硬性，不过关不算"可编码"）

1. **类型完整**：接口签名里引用的每个类型/结构，必须给出字段定义，不能只出现一个名字（如只写 `HookResult` 却不定义它）。
2. **API 真实**：每个被调用的框架/库 API 必须真实存在，禁止虚构参数或方法（照抄即报错）。
3. **标准可达**：每条可量化的成功标准（延迟 / 吞吐 / 准确率等），必须有可达的验证路径——拆成硬件规格 + 逐环节预算，而不是一句口号。

## 六层通用坑（逐层自查）

### E 执行循环
- 终止条件按**验证强度阶梯**取最高可行级（阶梯唯一定义处在本文件，V 层与各文档只引用）：**确定性规则 > 独立模型裁判（独立上下文、不看执行者推理、显式标准、迭代预算）> 模型自评（禁止）**。让模型给自己判卷 = 循环论证；无确定性规则可用时退到独立模型裁判，而不是掉进自评。
- 防跑飞三道保险：轮数上限 + token 预算 + 每节点超时。
- **墙钟时间要预算**（与上面的"防跑飞"是两件事）：防跑飞管"最多跑多久"，墙钟预算管"用户愿意等多久"；并行度必须封顶（有界池），依赖未理清不得并行。
- **错误必须作为观察结果回喂模型，禁止在循环里吞异常**（吞错 = 对模型撒谎）。错误要分类：瞬时（指数退避 + 抖动重试）/ 模型（带纠正重 prompt）/ 永久（fallback 链）/ 资源（checkpoint + 升级人类）。
- **打转检测**：连续 N 次相同工具名 + 参数指纹要能识别并打断，不能靠"轮次跑完"才发现。

### T 工具 / 组件
- 先明确是"固定管线"还是"动态 function-calling"；两者混着写会过度设计（给固定管线配一个没人调用的工具注册表）。
- "组件可插拔" = 依赖注入，别写成"给 LLM 动态调用的工具表"。
- **执行环境**：工具在哪跑（本地 / 沙箱 / 远程）？写操作的影响半径多大？**凭证绝不进执行环境**（走代理或受控入口注入）。
- **注册 ≠ 披露 ≠ 授权**：系统注册了 ≠ 展示给模型 ≠ 这次允许执行。敏感动作要能单独收紧。
- 工具描述要写清"做什么"（非"是什么"）、输出格式、约束、非直观参数示例——描述质量决定调用质量。

### C 上下文
- 阈值必须绑定度量空间（cosine / l2 / ip），换 embedding 时阈值需重标定。
- **每轮重新组装**，不更新 = 用过时信息；工具调用与其结果必须成对保留，不拆散。
- **预算要分配**（系统指令 / 历史 / 工具结果 / 参考资料各占多少），只给总量等于没设计。
- 外部来源内容要截断 + 标记成"待分析数据"，与指令区分开（防提示注入）。
- **前缀稳定 ≠ 不更新**（与上面"每轮重新组装"不是二选一）：内容可以每轮重取，**字节前缀不许变**——时间戳、随机 id、按相关性重排的工具表一律不许进前缀；工具定义与规则保持固定序，历史只追加；集合遍历、字典 key 顺序、空白与数值格式的**序列化必须确定**，语义相同而字节不同等于一个 token 都命中不了。**更新放尾部，稳定留头部。**
- **重写动作要记账**：压缩 / 摘要 / 报错重建 / 换模型 = 前缀重写 = 缓存整段失效。压缩前先算"这次要赔多少重算 token"，能分段压就别整体压（保住头部只压中段）。
- **昂贵且确定的中间结果要复用**：同参数工具调用、同版本文件解析、同一段会话摘要——但**失效条件必须先于缓存实现**（版本 / TTL / 权限），写操作与非幂等操作**禁止缓存**；脏缓存比不缓存更危险，读到的旧数据会被当成事实引用。

### S 状态存储
- 跨请求 / 多轮记忆必须落库，不能只写"内存态 = 单次请求"（否则多轮追问无从谈起）。
- 并发写要处理：WAL / 单写 / 连接池。
- 同步阻塞调用要隔离到线程池，别堵住异步事件循环。
- **会话恢复 ≠ 外部行动恢复**：重新加载进度不能证明超时的外部请求没成功 → 外部副作用必须有幂等键 + 状态查询 + 恢复策略。
- **记忆治理**：记忆要有可信度标记、归属（用户/项目）、失效条件；未验证的推测不得因"被写进记忆"升级为事实。
- **证据版本绑定**：验证结论只对被验证的版本有效；版本变更后旧结论要失效（补丁 A 的测试通过 ≠ 补丁 B 通过）。

### L 生命周期钩子
- 拦截点用真实 API 挂载，别虚构 API。
- 面向真实用户的鉴权必须写协议（JWT / SSO / OIDC），不能只写一句"校验身份"。
- 高危拦截要纵深，不能单点（前置、独立于分类器，防被误判绕过）。
- **人在回路四档**：自动执行 / 执行后告知 / 执行前确认 / 直接阻断——每个高危动作都要落在某一档，不能默认全放行。
- 审批量太大时可用模型做前置快筛，但**快筛模型不得看到执行者的推理过程**（否则等于让执行者自己审批）。

### V 评估
- 引用 / 溯源由**程序从可追溯来源绑定**，别让生成方自由发挥（否则可被伪造）。
- 评估走独立读路径（CQRS），不经过生成路径。
- **生成者不得兼任评估者**：评估方用独立上下文 + 独立评分标准，**不看执行者的推理过程**，只看产物与执行记录；并设迭代预算防评估死循环。
- **工具回执 ≠ 业务事实**：HTTP 200 / 退出码 0 不代表业务对象进入目标状态，要核对权威系统的实际状态。
- 评测环境要可比（同一基础设施、数据、预算），并防"绕过任务而非解决任务"（收紧工具能力、网络白名单而非黑名单）。

### 多 Agent 编排（若设计中含多 Agent）
- 先过 h-framework.md 的**编排决策卡**六步，确认不是过度分解。
- 反模式自查：共享可变状态 / 无界扇出 / 无超时无熔断 / 过度分解 / 子 Agent 结论未经核验直接采信。
- 子 Agent 要有独立上下文、独立权限、显式委派契约（交付什么、读写范围、依据版本、失败如何报）。

## 生产级横切关注点

- 可观测性：结构化日志 + 指标 + 全链路 tracing
- 限流 / 配额 / 防滥用（防知识库被逐条抽取）
- 成本核算：token 计数、语义缓存、**按模型档位的预算分配、单位任务成本核算、级联升级率监控**（升级率过高 = 分档失败，回查任务-模型分派表）；**缓存维度**：缓存命中率 / 命中 token 占比、重写触发次数与重算 token 量——只看"花了多少"会漏掉"本可不重算的那部分"
- 墙钟与体感：端到端墙钟预算与并行度上限、首字节延迟目标、是否流式输出、可中断点与取消后的副作用清单
- 评测反馈闭环：badcase 回流、回归门禁
- 内容安全纵深：prompt injection 防御、输出过滤
- 数据治理：备份 / 恢复、日志保留期、脱敏 salt 统一管理
- 知识库版本化、灰度发布与回滚

## 诚实边界

- 引用校验能防"无中生有"，防不了"张冠李戴"（引用是真的、结论却用错了），需人工抽查兜底。
- 主观类任务若无 ground truth，评估只能覆盖客观部分，其余标注为未知区，不假装能自动评分。
- 本清单堵的是"设计里反复出现的共性坑"，**不等于业务验收**；业务侧"什么算做完"仍由用户定义。

## 部署 / 发布检查单（P2-3 新增；P4 必过）

> 对应 team-lead §五.5 三档发布路径。任一项未过 = P4 未完成。

### 档 1：静态站点 / 前端 Web / Node HTTP

- [ ] 构建产物存在（`dist/` / `build/` / `out/` 目录非空）
- [ ] 入口可启动（启动命令 + 端口 + 启动日志无致命错误）
- [ ] 关键路径人工/curl 验证：首页 200 + 一条主流程链路 200
- [ ] 静态资源引用无 404（CSS/JS/字体/图片）
- [ ] 环境变量/配置文件在 README 中明示

### 档 2：云应用（DB / 用户登录 / 文件存储 / LLM 调用）

- [ ] `cloud-service` 接入清单全过：
  - [ ] 库表迁移完成（schema 文件存在 + 迁移命令执行成功）
  - [ ] 鉴权配置就位（SSO/OIDC 回调 URL 注册；JWT 密钥生成）
  - [ ] 密钥不进仓库（`.env.example` 存在 + `.gitignore` 排除 `.env`）
  - [ ] 调用配额核验（LLM 调用预算 = 单次预算 × 预期 QPS；DB 写入 QPS 不超限额）
- [ ] 写操作的幂等键存在（防重复提交）
- [ ] 健康检查端点（`/healthz` / `/readyz`）可访问
- [ ] 备份策略就位（DB 备份周期 + 保留时长）

### 档 3：CLI 工具 / 库 / 桌面脚本

- [ ] 安装命令（`pip install .` / `npm install -g` / `brew install`）README 中明示
- [ ] 运行命令 + 一个最小可复现示例在 README 中给出
- [ ] 依赖声明完整：`pyproject.toml` / `package.json` / `requirements.txt` / `Cargo.toml` 至少一项存在且与代码 import 一致
- [ ] 入口文件可执行权限正确（CLI 场景）
- [ ] 帮助命令（`-h` / `--help`）输出可用

### 三档共有

- [ ] 交付报告「发布路径」一节有这一档的逐项打勾表
- [ ] 域名 / 端口 / 路径在最终交付里明示
- [ ] 回滚方案说明（一键回滚命令或 git tag 锚点）
