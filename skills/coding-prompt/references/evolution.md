## 7. 进化协议

> 触发：更新技能 / update skill
> 常规修改目标：`references/learnings.md`（经验层唯一入口）

### 写入位置（先看清环境再决定写哪）

| 环境 | 可写位置 | 说明 |
|------|---------|------|
| **团队语境**（本技能内嵌于 agent-harness-expert 专家团） | `<项目>/.harness-kb/learnings.md` | 插件目录不可写且写入会被包升级冲掉；项目内才是团队约定的沉淀位|
| 独立使用本技能（技能位于用户可写目录） | `references/learnings.md` | 此时包内 learnings.md 才是可写目标 |

> 包内 `references/learnings.md` 在**任何环境都只读**，只作格式样板与只读基线。团队语境下的写入由编码工程师执行，格式仍按下述分节。

### 文件权限矩阵

> 权限按「**独立使用本技能**」的环境列出；团队语境下所有包内文件一律只读，见上方写入位置表。

| 文件 | 权限 | 原因 |
|------|------|------|
| `SKILL.md` | 🔒 只读 | 宪法——定义技能本身 |
| `references/checklist.md` | 🔒 只读 | 结构清单——完整性优先于灵活性 |
| `references/principles.md` | 🔒 只读 | 公理级规则——通用最佳实践 |
| `references/patterns.md` | 🔒 只读 | 沟通机制——客观模式 |
| `references/anti-patterns.md` | 🔒 只读（晋升例外见下） | 精选参考——通过 learnings 晋升生长 |
| `references/templates.md` | 🔒 只读 | 工作流结构——行为一致性 |
| `references/structure.md` | 🔒 只读 | 架构智慧——浓缩的条件→动作 |
| `references/evolution.md` | 🔒 只读 | 进化协议本身 |
| `references/learnings.md` | 🔒 只读（格式样板）/ ✅ 独立使用时可写 | 个人经验层——经验的唯一入口；团队语境写入项目内|

**规则**：任何修改经验层以外文件的尝试都是违规。拒绝并重定向到经验层（团队语境 = 项目内 learnings.md）。
**唯一例外**：晋升流程（见下）。

### 第 1 步：采集（低门槛）

先读经验层（团队语境 `<项目>/.harness-kb/learnings.md`；独立使用 `references/learnings.md`）了解已有经验，没有则视为无已有经验，然后从当前会话提取：
- 有效且**可复用**的模式（非一次性）
- 值得记录为**警告**的坑
- 协作中发现的个人偏好

**采集阶段不追求精炼**——一两句话记下即可，甚至可以粗糙。精炼发生在写入时（第 4 步）。

**过滤标准**（只需满足前两条）：
1. 可复用：适用于未来会话
2. 非冗余：未被现有规则覆盖

**主动建议沉淀的时机**（不必等用户说「更新技能」）：
- 用户驳斥了某个警报/建议，且理由有价值 → 建议记为个人偏好或边界条件
- 用户连续 2-3 轮纠正 AI 的同类错误 → 建议记为反模式
- 发现了 D1-D16 未覆盖的 AI 失败模式 → 建议记为反模式（成熟后可晋升为新 D 编号）

### 第 2 步：提案

以 learnings.md 的分节格式呈现结构化提案：

```
## 经验沉淀提案

### 被验证有效的模式
- [模式名]
  - **规则**: <具体做法，一句话>
  - **触发场景**: <何时适用>
  - **来源**: <本次会话的什么情况>

### 反模式（踩过的坑）
- [问题名]
  - **表现**: <AI 容易犯的具体错误>
  - **预防**: <prompt 里加什么约束>
  - **来源**: <本次会话的具体情况>

### 个人偏好
- [偏好项]
  - **规则**: <偏好描述>
```

某节无内容则省略。

### 第 3 步：确认（强制）

**任何写入前必须获得用户明确确认。** 这是本技能的最高优先级规则。

### 第 4 步：写入经验层

确认后：
1. 读当前经验层文件（不存在则按分节格式新建，团队语境建在 `<项目>/.harness-kb/` 下）
2. 新内容匹配现有格式——在这一步做架构师级提炼：抽象出模式而非复述事件，一条一个洞见，无废话
3. 新条目与已有条目**重叠或取代**时，合并更新旧条目而非追加重复
4. 追加或更新到对应分节
5. 更新头部版本号和「最后更新」日期
6. 写回完整文件

> **包内不写**：团队语境下绝不写插件目录内的 `references/learnings.md`（不可写 + 升级会被冲掉）。包内该文件仅作格式样板。

### 防膨胀准则

- **条目格式**：每条最多 2-4 行。不要冗长叙述，不要多段案例。
- **合并优先于累积**：新条目与旧条目重叠时，合并精炼而非追加。目标是增长的智慧，不是增长的文件。
- **风格一致**：所有条目遵循现有格式。不引入新的分节类型。

### 晋升路径

当 learnings 中的条目**被 3+ 次会话验证**且具有普遍性（不限于个人偏好）时，可晋升：
- 反模式 → `anti-patterns.md` 新增一行
- 新的 AI 失败模式 → `checklist.md` 新增 D 编号，并同步进 SKILL.md 的 Mode 2 警报表

**晋升触发**：用户明确说「晋升 <条目> 到 <文件>」。晋升是对该条目的一次性解锁，完成后相关文件恢复只读。

### learnings 与 Mode 2 的联动

技能激活（进入 Mode 2）时，读取 `learnings.md` 的「反模式」分节（不存在则跳过），将其纳入主动监控范围——个人踩过的坑应该实时生效，而不是只在显式优化时被读到。learnings.md 保持精简时此成本可忽略。
