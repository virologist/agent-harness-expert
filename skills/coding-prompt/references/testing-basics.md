## 8. 测试基础（测试工程师专用）

> 供 P3 独立验证使用。只放对抗性用例设计、执行证据格式、问题分级三件事，不覆盖编码规范。

### 8.1 对抗性用例设计三问

每个核心功能至少过一遍：

1. **边界值**：输入为空 / 单条 / 超大量 / 极长字符串 / 0 与负数 / 最大值附近，行为是否符合预期？
2. **非法输入**：错误类型、错误格式、缺失字段、多余字段、恶意构造（特殊字符、路径穿越、超长注入），是否被拒绝且报错友好？
3. **依赖失效**：网络断开、文件不存在、权限不足、下游超时，是否优雅降级而非崩溃或静默吞错？

只测 happy-path = 未完成测试。每个错误分支至少一个用例。

### 8.2 执行证据格式

「已验证」必须有真实执行证据，缺一即视为未验证：

- **命令**：原样贴出（含工作目录与参数）。
- **输出**：原始输出（截取关键段也可，不得转述、不得伪造）。
- **退出码**：`echo $?` 的实际值（或 pytest/unittest 的通过统计行）。

无执行输出 = 未完成。弱化测试（删断言/放宽预期/跳过用例）一票否决。

### 8.3 问题分级标准

| 级别 | 判定线 | 处理 |
|---|---|---|
| **阻断** | 核心功能跑不通 / 数据丢失或损坏 / 安全漏洞 / 验收标准未达成 | 不得交付，退回 P2 |
| **缺陷** | 功能可用但边界/异常场景出错、报错不友好、性能明显不达标 | 记录，由管家节点决定是否修复后交付 |
| **建议** | 可维护性、命名、冗余等改进空间 | 记录，不阻塞交付 |

测试工程师只报问题、不修改实现（独立验证原则）。

### 8.4 必跑命令清单（最小验证集）

「功能可用」的结论必须建立在以下三类命令**真实执行**之上，缺一类即视为未完成测试：

1. **启动验证**：项目能以文档声明的方式启动（`npm run dev` / `python3 main.py` / 入口命令等），启动日志无致命错误。
2. **最小端到端用例**：至少一条覆盖核心功能主路径的真实调用（发一条真实请求 / 跑一个真实脚本 / 调一次入口函数），并贴出响应输出。
3. **错误路径用例**：至少一条故意构造的错误输入（非法参数 / 缺失依赖 / 空输入），验证被拒绝且报错友好，而非崩溃或静默吞错。

每条命令按 §8.2 格式留证（命令 + 输出 + 退出码）。此外，交付物若使用 CodeBuddy Agent SDK，必须追加执行 §9 的 SDK 确定性校验清单（`sdk-checklist.md`）。
