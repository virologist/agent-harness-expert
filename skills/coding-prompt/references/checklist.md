## 1. 提示词诊断清单

用于 **Mode 1（显式优化）**。逐项检查，只报告明确触发的信号——拿不准就跳过。

| # | 信号 | 检查要点 |
|---|------|----------|
| D1 | **无背景** | 缺少项目上下文，不熟悉代码库的 AI 能否理解任务？ |
| D2 | **无约束** | 有没有明确的「不能」边界？模糊的「应该」没有硬限制就会漂移。 |
| D3 | **无交付物** | 期望的输出格式和质量标准是否明确说出？ |
| D4 | **无场景** | 需求是从用户视角描述的，还是只有技术术语？ |
| D5 | **无诊断** | 是否要求 AI 先诊断现状再行动？（见原则 2.4） |
| D6 | **无质疑** | 非平凡功能，是否要求 AI 质疑功能本身的必要性？（见原则 2.5） |
| D7 | **无优先级** | 3+ 个需求却没有明确的优先级排序？ |
| D8 | **无输出控制** | 期望的响应格式未指定？（只要代码？要解释？要表格？） |
| D9 | **无依赖声明** | 任务依赖的未完成工作是否声明为前置条件？ |
| D10 | **上下文过期** | 关键约束上次明确陈述距今是否已超过 ~10 轮对话？ |
| D11 | **规则匹配偏见** | 是否在选择硬编码规则/正则/打分，而 LLM 原生方案更简单更好？ |
| D12 | **假完成** | 是否声称「完成」但交付的是 stub、TODO、占位返回或示例数据？ |
| D13 | **缺回归测试** | 代码完成/更新后，是否未验证未修改的功能仍正常？ |
| D14 | **范围蔓延** | 是否修改了与任务无关的代码、重构了未要求的部分、或添加了未请求的功能？ |
| D15 | **伪称已运行** | 是否声称「测试通过/已验证」但没有真实执行的命令与输出？ |
| D16 | **弱化测试** | 是否为让测试通过而删除断言、放宽预期值、或跳过失败用例？ |

**注**：D11–D16 同时用于 **Mode 2（主动监控）** 的警报。其余信号仅在显式要求审查时报告。
